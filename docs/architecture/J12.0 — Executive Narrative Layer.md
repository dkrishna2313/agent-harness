# J12.0 — Executive Narrative Layer

**Status:** Complete. Architectural milestone — no reasoning, Functional Agent
prompts, Strategic Reasoning objects, contracts, CLI surface, or any existing
deliverable behaviour changed. 2613 tests pass (34 new).

**Date:** 2026-07-03

---

## 1. Motivation

The platform now has three separate views of the same Strategic Reasoning
Graph:

| Deliverable | Assembles narrative from |
|---|---|
| `MarkdownReportGenerator` | `_build_j7_executive_report(context)` + many private helpers |
| `ExecutiveBriefGenerator` | 10 private `_build_*` functions, each reading AgentContext |
| `StrategyDeckGenerator` | 12 private `_build_slide_*` functions, each reading AgentContext |

Each generator independently reads `decision_analysis["rationale"]`,
`executive_confidence["board_recommendation"]`, and similar fields.
If the Strategic Reasoning Graph changes shape, every generator must be
updated independently. If two generators produce inconsistent executive
summaries, there is no authoritative version.

J12.0 introduces **`ExecutiveNarrative`** — a canonical business object that
represents the executive storyline once, assembled once from the completed
Strategic Reasoning Graph, reusable by all future deliverable generators.

```
    ▼                    ▼                   ▼                      ▼    │

(J12.x — future)         (J12.1 — next)           (J12.2 — future)       │

    ◄─────────────────────── context.executive_narrative ◄──────────┘    │
    ◄─────────────────────── trace["executive_narrative"] ◄──────────────┘
```

J12.0 introduces the layer and the builder. Generators are **not migrated in
this milestone** — that begins in J12.1.

One method, 11 private `_extract_*` helpers:

| Field | Source |
|---|---|
| `decision` | `research_object["decision_architecture"]["decision_statement"]` → `decision_architecture.decision_statement` |
| `executive_summary` | `strategic_synthesis["executive_summary"]` → `decision_analysis["executive_summary"]` |
| `recommended_option` | `decision_analysis["recommended_option_id"]` looked up in `strategic_options` (real schema: `description`, `estimated_time_horizon`, `capital_intensity`, `confidence`) |
| `why_this_option` | `decision_analysis["rationale"]` |
| `key_tradeoffs` | `strategic_synthesis["key_tradeoffs"]` → `decision_analysis["comparison_dimensions"]` |
| `key_risks` | `risks` sorted by severity (top 5); extracted fields: `risk_id`, `statement`, `severity`, `likelihood` |
| `key_opportunities` | `opportunities` (top 5); extracted: `opportunity_id`, `title`, `impact`, `description` |
| `critical_assumptions` | `assumptions` sorted by importance (top 5); extracted: `assumption_id`, `statement`, `importance`, `confidence` |
| `executive_confidence` | `executive_confidence` subset: `overall_confidence`, `decision_readiness`, `board_recommendation`, `confidence_rationale` |
| `immediate_actions` | `recommendation_portfolio["near_term"]` ids looked up in `recommendations`; extracted: `id`, `title` |
| `validation_priorities` | `executive_confidence["validation_priorities"]` |

Sets `context.executive_narrative = narrative.to_dict()` on return.
No LLM, no Functional Agent, no reasoning field mutated.

## 4. Design decisions

- **`ExecutiveNarrative` is a flat dataclass, not a nested object graph.**
  All fields are strings, lists, or shallow dicts — no nested `Risk` objects,
  no circular references. This keeps `to_dict()`/`from_dict()` trivial and
  makes the object genuinely portable across generators without pulling in
  the full domain model.
- **All 11 fields always present in `to_dict()`.** Consumers can read
  `narrative["key_risks"]` without a `KeyError` guard — empty list is
  meaningful (no risks computed), absent key is not.
- **Reference/summarise, don't duplicate.** `key_risks` carries
  `{risk_id, statement, severity, likelihood}` — the identifying and
  communication-relevant subset — not the full risk object. The full
  `AgentContext.risks` list remains the authoritative source.
- **`recommended_option` uses the real schema.** `description`,
  `estimated_time_horizon`, `capital_intensity`, `confidence` — not the
  legacy `posture`/`required_capabilities` fields the J7 report renderer
  reads. Consistent with `ExecutiveBriefGenerator` and `StrategyDeckGenerator`
  (J11.1/J11.3 decision).
- **`key_tradeoffs` from `strategic_synthesis["key_tradeoffs"]` first.**
  If `StrategicSynthesisAgent` explicitly outputs named tradeoffs in a future
  milestone, they take precedence over `comparison_dimensions`. Comparison
  dimensions are the correct fallback today.
- **Builder is an instance method, not a static function.** Allows future
  configuration injection (max_risks, max_assumptions, preferred fields) via
  `__init__` without changing the call site.
- **No generator migration in J12.0.** `ExecutiveBriefGenerator` and
  `StrategyDeckGenerator` are unchanged — they continue reading directly from
  AgentContext. Migration begins at J12.1, starting with `ExecutiveBriefGenerator`.
