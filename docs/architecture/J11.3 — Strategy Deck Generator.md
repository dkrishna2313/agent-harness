## 1. Motivation

J11.2 demonstrated the Deliverable Bundle: multiple generators consuming the
same completed `AgentContext` in one envelope, with the `DeliverableBundleGenerator`
as the orchestrator. J11.3 adds the third concrete generator —
`StrategyDeckGenerator` — and updates the default bundle to produce three
deliverables from one reasoning graph.

A strategy deck is the natural consulting artefact between a full narrative
report (J11.0) and a one-page brief (J11.1): a slide-by-slide rendering of
the Strategic Reasoning Graph suitable as the source file for PowerPoint
conversion (J11.4).

## 2. What shipped

### New file — `functional_agents/deliverables/strategy_deck.py`

**`StrategyDeckGenerator(DeliverableGenerator)`**, `deliverable_type =
"strategy_deck"`. `generate(context, output_path)` calls
`build_strategy_deck_content(context)` then `write_markdown()` — the same
write path every other generator uses.

**`build_strategy_deck_content(context) -> str`** assembles 12 slides
separated by `---`, each beginning with `# Slide X — Title`. Every section
is a pure function reading already-computed `AgentContext` fields:

| Slide | Source field(s) |
|---|---|
| 1. Executive Decision | `research_object["decision_architecture"]["decision_statement"]`, `decision_analysis["recommended_option_id"]`, `preferred_option` |
| 2. Client Situation | `engagement` (title, client, industry, decision_horizon, constraints), `decision_architecture`, `context.question` |
| 3. Executive Summary | `strategic_synthesis["executive_summary"]` → `decision_analysis["executive_summary"]` |
| 4. Strategic Options | `strategic_options` comparison table; recommended option marked ✓; top advantages |
| 5. Decision Matrix | `decision_analysis["comparison_dimensions"]`, `option_rankings`, `rationale` |
| 6. Strategic Risks | `risks`, sorted by severity (top 5), with mitigations |
| 7. Strategic Opportunities | `opportunities` (up to 6) |
| 8. Critical Assumptions | `assumptions`, sorted by importance (top 5) |
| 9. Executive Confidence | `executive_confidence` (overall, readiness, board recommendation, unknowns, validation priorities) |
| 10. Immediate Actions | 30/90/180-day roadmap from `recommendation_portfolio["near_term"/"medium_term"/"long_term"]` |
| 11. Supporting Evidence | `surviving_hypotheses` (preferred) → `hypotheses` fallback |
| 12. Appendix (optional) | `profiles`, `multi_profile_analysis`, `executive_confidence["critical_unknowns"]` — omitted when all are empty |

### `functional_agents/deliverables/__init__.py`

Registers `StrategyDeckGenerator` alongside the existing two generators on
`default_registry` under `"strategy_deck"`.

### No other files changed

`report_agent.py`, `context.py`, `pipeline_trace.py`, `run_agent.py`,
`cli.py` — all untouched. `ReportAgent`'s default run still only ever
requests `"markdown"`.

## 3. Design decisions

- **`# Slide X — Title` headings + `---` separators.** Each slide is a
  first-level heading so the deck is trivially parseable into slide objects
  by future renderers (J11.4 PowerPoint, web deck tools). `---` between
  slides is standard Markdown horizontal rule — renderers can split on it.
- **`_recommended_id()` helper shared across slides.** Slides 1 and 4 both
  need the recommended option id; the helper avoids repeating the
  `decision_analysis["recommended_option_id"]` → `preferred_option["option_id"]`
  fallback chain.
- **Slide 4 uses the real `StrategicOptionItem` schema** (`description`,
  `estimated_time_horizon`, `capital_intensity`, `confidence`, `advantages`,
  `disadvantages`) — same policy as `executive_brief.py`, not the legacy
  report renderer's schema.
- **Slide 10 reads `recommendation_portfolio["near_term"/"medium_term"/"long_term"]`**,
  not `strategic_option_portfolio` (which is always `{}` in practice), for
  the 30/90/180-day roadmap.
- **Slide 11 prefers `surviving_hypotheses`** (post-ChallengeAgent filter) over
  the raw `hypotheses` list — the deck presents validated evidence, not all
  initial hypotheses.
- **Appendix optional.** When `profiles`, `multi_profile_analysis.profiles`,
  and `executive_confidence.critical_unknowns` are all empty, slide 12 is
  omitted from the join (empty string is falsy in the `if s` filter).
- **No CLI changes.** The existing `functional_agents.cli run --engagement`
  path is unchanged; bundle generation with `"strategy_deck"` is exercised
  via direct API.
