# J11.1 — Executive Brief Generator

**Status:** Complete. Presentation-only milestone — no reasoning, Functional
Agent prompts, Strategic Reasoning objects, contracts, or CLI surface
changed. Existing markdown report output is byte-for-byte identical
(verified below). 2516 tests pass (17 new).

**Date:** 2026-07-03

---

## 1. Motivation

J11.0 introduced the Deliverables Framework — a registry-dispatched seam
between the Strategic Reasoning Graph on `AgentContext` and presentation —
with exactly one concrete generator (`MarkdownReportGenerator`). J11.1
validates that seam by adding a second, genuinely different deliverable
(`ExecutiveBriefGenerator`) that consumes the *same* completed reasoning
graph without rerunning any Functional Agent.

## 2. What shipped

### New file — `functional_agents/deliverables/executive_brief.py`

- **`ExecutiveBriefGenerator(DeliverableGenerator)`**, `deliverable_type =
  "executive_brief"`. `generate(context, output_path)` calls
  `build_executive_brief_content(context)` (pure text assembly) then
  `write_markdown()` — the same write path `MarkdownReportGenerator` uses.
- **`build_executive_brief_content(context) -> str`** assembles a 10-section
  brief, each section a small pure function reading already-computed
  `AgentContext` fields:

  | Section | Source field |
  |---|---|
  | 1. Executive Decision | `research_object["decision_architecture"]["decision_statement"]`, `preferred_option`/`strategic_options` |
  | 2. Executive Summary | `strategic_synthesis["executive_summary"]` (falls back to `decision_analysis["executive_summary"]`) |
  | 3. Recommended Strategic Option | `decision_analysis["recommended_option_id"]` looked up in `strategic_options` |
  | 4. Why This Option | `decision_analysis["rationale"]`, `comparison_dimensions`, `option_rankings` |
  | 5. Key Strategic Risks (Top 5) | `risks`, sorted by severity, truncated |
  | 6. Critical Assumptions | `assumptions`, sorted by importance, truncated |
  | 7. Executive Confidence | `executive_confidence` |
  | 8. Immediate Executive Decisions | `recommendation_portfolio["near_term"]` looked up in `recommendations` |
  | 9. Validation Priorities | `executive_confidence["validation_priorities"]` |
  | 10. Appendix (optional) | `profiles`, `executive_confidence["critical_unknowns"]` — omitted entirely when both are empty |

  Every value is a direct read (or a presentation-layer sort/truncation of
  already-computed data, the same category of operation
  `_build_j7_executive_report` already performs) — no new inference.

### `functional_agents/deliverables/__init__.py`

Registers `ExecutiveBriefGenerator` alongside `MarkdownReportGenerator` on
`default_registry`, under `"executive_brief"`.

### No other files changed

`report_agent.py`, `context.py`, `pipeline_trace.py`, `run_agent.py`,
`cli.py` — all untouched. `ReportAgent`'s default run still only ever
requests `"markdown"`; registering a second generator does not change what
a normal pipeline run produces.

## 3. Design decisions

- **Real production schema, not the legacy renderer's schema.** Research
  before implementing surfaced a pre-existing mismatch: the actual
  `StrategicOptionItem` schema `StrategicOptionAgent` produces
  (`description`, `estimated_time_horizon`, `capital_intensity`,
  `confidence`, `advantages`, `disadvantages`) does not match the field
  names `report_agent.py`'s J7 report renderer reads via `.get()`
  (`posture`, `strategic_logic`, `required_capabilities`, `dependencies`).
  This is a latent, pre-existing gap in the codebase, not something J11.1
  was asked to fix — but `executive_brief.py` renders against the *real*
  schema so this new deliverable doesn't inherit the same sparse-render
  behaviour. Not fixed in the existing report (out of scope; presentation-only
  milestone, no existing behaviour may change).
- **`strategic_option_portfolio` is dead — used `recommendation_portfolio`
  instead.** Research confirmed no agent in the codebase ever populates
  `AgentContext.strategic_option_portfolio` (always `{}}` in practice).
  "Immediate Executive Decisions" instead reads
  `recommendation_portfolio["near_term"]`, which genuinely is populated by
  `RecommendationAgent` — avoiding a section that would always render empty.
- **Self-contained module, no cross-import from `report_agent.py`'s
  helpers.** Unlike `MarkdownReportGenerator` (which wraps the exact
  pre-existing rendering logic via extraction), `executive_brief.py` is
  new presentation code with its own condensed format — it doesn't reuse
  `report_agent.py`'s private section builders, keeping the two generators
  independently auditable.
- **Sorting/truncation is presentation, not reasoning.** Top-5 risks by
  severity and top-5 assumptions by importance are read-only
  sorts/slices of already-computed lists — the same category of operation
  the existing J7 report already performs (e.g. sorting assumptions by
  importance). No new judgment is introduced about which risks/assumptions
  matter; the underlying agents already computed severity/importance.
- **Graceful degradation everywhere.** Every section renders an italicized
  "not available" placeholder rather than crashing or omitting the header
  when its source field is empty — verified by
  `test_executive_brief_degrades_gracefully_on_empty_context`.
- **No CLI changes.** Per the spec, `ExecutiveBriefGenerator` is exercised
  via direct registry calls for validation (a "temporary developer hook,"
  used only for this validation run — not committed to the codebase).

## 4. Verification

- **Byte-for-byte identical markdown, isolated from environment noise**:
  the J11.1-specific files (`executive_brief.py`,
  `deliverables/__init__.py`, `test_executive_brief.py`) were stashed, a
  mock pipeline run captured from the same working directory, the stash
  restored, and the pipeline re-run from the same directory. `report.md`
  diffed empty — registering a second generator changes nothing about the
  default markdown output.
- **Same reasoning graph, no additional agent execution**: ran
  `Orchestrator.run_from_engagement()` once against
  `engagements/hyperscaler_ai_strategy.yaml` (mock mode), producing the
  markdown deliverable via `ReportAgent` as always. Then, on that *same*
  already-completed `AgentContext` (no second pipeline run),
  called `default_registry.generate(ctx, DeliverableRequest(type="executive_brief"), ...)`
  directly. `ctx.agent_history` after both calls lists only the original
  20 agents from the one pipeline run — confirmed no Functional Agent ran
  a second time to produce the brief.
- **AST-verified**: `test_executive_brief_generator_never_touches_functional_agents`
  parses `executive_brief.py`'s source and asserts no imported symbol ends
  in `Agent` and `FunctionalAgent` is never imported.
- 2516 tests pass, including 17 new in `tests/test_executive_brief.py`:
  registration, section-header presence, content correctness against the
  *real* `StrategicOptionItem` schema (a fixture deliberately built fresh
  rather than reusing `test_report_agent_j7.py`'s legacy-schema fixture),
  risk/assumption sort order, top-5 truncation, appendix
  presence/omission, graceful degradation on an empty context, the
  never-invokes-a-Functional-Agent AST check, and confirmation that
  `ReportAgent`'s default run still only ever produces one `"markdown"`
  deliverable.
